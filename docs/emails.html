How a message is put together

Every body is a template — none are built as HTML strings in a controller. email_body() renders one and hands $settings in for you, so the site name and the support address are always filled. Nine of the ten templates extend emails/layout.php, which supplies the violet banner across the top and the two paragraphs at the bottom. Only contact.php stands alone as a document of its own.

A plain-text alternative is generated from each body by stripping the tags, so text-only clients get something readable and spam filters see a proper multipart message. A send that fails is logged and stashed in session tempdata under email_failures, so the page that follows can say so rather than pretending it went.

Who can turn what off

Six of the eleven are optional. Each has a numeric code; a user's blocked codes live in users.u_email_blocked as a comma-separated list, and every send site asks userAllowsEmail() before going ahead. The list is defined in app/Config/AppSettings.php:222, and Manage Email only offers an account the types its own side can actually receive.

Code Label on the Manage Email screen Template Offered to
1Welcome (on registration)welcomeBoth
2Account approvedaccount-approvedBoth
3Shift posted (your shift is live)shift-postedEmployers
4Booking confirmation (as applicant)booking-applicantApplicants
5Booking confirmation (as employer)booking-employerEmployers

The other five have no switch on purpose: the password reset, the cancellation, the contact form, the delivery test, and the ad-hoc broadcast.
